- **Data Factory:** `Microsoft.DataFactory/datafactories` is a documented legacy
  type, not a typo. Five recommendations now explicitly maintain v2 applicability
  using `factories`, with qualified Key Vault dependency recovery, Git/CI/CD,
  self-hosted runtime recovery, network recovery and component-specific zone
  resilience guidance. The unknown original version intention is not invented.
- **WAF:** diagnostics belong to Front Door or Application Gateway hosts, not
  merely to a WAF policy. The corrected applicability keeps SKU, WAF-enabled,
  classic/Standard/Premium, origin-isolation and regional-proxy distinctions.
  Global Front Door is not described as running inside a landing-zone VNet.
- **Databricks:** the Photon-title/Spark-recovery contradiction is resolved as a
  resilient distributed-execution requirement under **Reliability**. Photon
  performance, job retries, streaming checkpoints and regional recovery remain
  separate concerns. The original GUID and Photon-containing canonical name
  remain unchanged; no absent upstream GUID mapping is invented.
- **Key Vault:** clarify control-plane versus data-plane authorization, audit
  resource logs, integrated versus external certificate renewal, and the specific
  APIM, VM, AKS CSI and Application Gateway integration/rotation limitations.
- **Storage duplicates:** consolidate identical control-plane lock requirements
  and equivalent Last Sync Time assessment guidance. Blob/container recovery
  and other unresolved classification/priority conflicts remain separate.

equate v1 and v2. Friendly service aliases work in saved CLI/UI filters and in

not inferred from a host ARM type alone. A plain Application Gateway retains its
product label; unrelated CDN profiles are not automatically called Front Door
